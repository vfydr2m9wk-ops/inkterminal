Can the iPhone become Zoom’s camera on the iPad?

This page checks the browser features available on this device and explains the current technical boundary. It does not change your Zoom settings or request camera access.

Direct injection into the normal Zoom Web meeting is not available to a webpage.

InkTerminal can receive the iPhone’s video in this Safari tab, but a separate website cannot register that stream as a system camera or pass it directly into Zoom’s camera selector. This is a browser/iPadOS boundary, not a missing JavaScript setting.

What can work instead?

Option 1 — Keep the existing Zoom meeting on the iPad

Use InkTerminal to receive and preview the iPhone feed, but select the iPad’s built-in camera in Zoom. The iPhone feed will not be sent to the other participants as the Zoom camera.

Option 2 — Use the iPhone as a real webcam on a computer

This is the supported path already built into InkTerminal: receive the stream on Windows and use the InkTerminal virtual camera or OBS Virtual Camera, then select that camera in Zoom. A desktop OS can expose a virtual camera to other apps.

Option 3 — Build a separate Zoom-powered meeting interface

Zoom’s Video SDK can power a custom meeting application, but this is not a drop-in camera for an ordinary Zoom meeting. It requires Zoom developer credentials and a secure token service; secrets must not be embedded in this static GitHub Pages site.

Zoom Video SDK docs

Why we are not adding a fake “Connect to Zoom” button

A button cannot bridge isolated browser tabs or create a system-level camera device. Adding one would appear to work in a demo while leaving Zoom participants without the iPhone video. The next useful experiment is to test supported system-level routes, not to modify the existing WebRTC stream in a way that cannot reach Zoom.
